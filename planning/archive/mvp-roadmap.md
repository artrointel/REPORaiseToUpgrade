# MVP 기획 로드맵 (이전 기획)

## 목표

거대한 랜덤 이벤트 시스템을 한 번에 만드는 대신, 하나의 변칙이 순정 참여자에게 실제로 이해되고 재미를 만드는지 먼저 증명한다.

## 0단계: 게임 코드 조사

- 레벨 생성과 가치품 배치의 호스트 권한 지점을 찾는다.
- 적 사망과 런타임 스폰의 권한 지점을 찾는다.
- Photon으로 이미 동기화되는 상태와 로컬 전용 상태를 구분한다.
- 중도 참가 시 기존 스폰 오브젝트가 어떻게 복원되는지 확인한다.

산출물은 메서드 이름, 호출 시점, 소유권, 순정 클라이언트 관찰 결과를 기록한 기술 메모다.

## 1단계: 수직 프로토타입

`M-002 현상금` 하나를 우선 권장한다. 원인(적 사망)과 결과(가치품 등장)가 가깝고, 기존 적과 가치품만 사용하며, 재미 여부를 짧은 실험으로 판단할 수 있기 때문이다.

최소 범위:

- 호스트에서만 동작
- 대상 적 1종
- 순정 가치품 1개 스폰
- 한 스테이지당 발동 횟수 제한
- 설정 UI 없이 고정값 사용
- 오류 시 보상만 생략하고 원래 적 사망은 유지

## 2단계: 이해도 플레이테스트

테스터에게 규칙을 설명하지 않고 한 판을 플레이시킨다. 종료 후 다음을 묻는다.

1. 평소와 달랐던 점은 무엇인가?
2. 무엇 때문에 그 일이 일어났다고 생각하는가?
3. 그 변화 때문에 행동을 바꿨는가?
4. 재미, 혼란, 불공정 중 무엇을 느꼈는가?
5. 다시 등장한다면 어떤 전략을 쓰겠는가?

3명 이상의 순정 참여자 중 2명 이상이 핵심 인과관계를 알아차리지 못하면 시각적·시간적 연결을 개선하거나 후보를 교체한다.

## 3단계: 변칙 시스템화

첫 프로토타입이 통과한 뒤에만 공통 시스템을 만든다.

- `MutatorDefinition`: ID, 강도, 호환 태그, 가중치
- `MutatorSelector`: 중복 방지와 위험 예산 계산
- `MutatorLifecycle`: 스테이지 시작, 활성화, 종료, 정리
- `HostAuthorityGuard`: 호스트 여부 중앙 검사
- `SafetyFallback`: 예외 격리와 기능별 비활성화
- 구조화 로그: 선택, 발동, 스폰, 제외 사유

## 4단계: 세 가지 변칙 완성

- 관계 변화: `현상금`
- 위치 변화: `보물 소굴`
- 시간 변화: `늦은 출근`

세 변칙을 개별 검증한 뒤 연속 스테이지에서 반복 체감과 선택 분산을 확인한다. 이 단계까지는 두 변칙을 동시에 적용하지 않는다.

## 5단계: 밸런스와 조합

- 플레이어 수별 위험/보상 보정
- 순정 난이도가 높을 때 RepoHell 강도 감산
- 최근 등장 기록과 변화 축 중복 방지
- 중도 참가, 재접속, 게임 오버, 저장 재개 검증
- 안전한 조합만 화이트리스트로 추가

## MVP 완료 조건

- 최소 3개의 변칙이 서로 다른 플레이 결정을 만든다.
- 순정 참여자가 설명 없이 각 변칙의 핵심 관계를 대체로 이해한다.
- 방장 단독 설치 테스트를 모두 통과한다.
- 같은 변칙이 반복되어도 배치와 상황에 따라 다른 이야기가 나온다.
- 순정 스테이지 변화가 강할 때 과도한 난이도 중첩이 발생하지 않는다.
