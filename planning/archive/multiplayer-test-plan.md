# 멀티플레이 검증 계획 (이전 기획)

## 목적

방장에게만 RepoHell이 설치된 혼합 로비에서 순정 참여자가 추가 설치 없이 핵심 기능을 온전히 경험하고, 게임 진행과 저장이 안전한지 검증한다.

## 테스트 구성

최소 두 개의 분리된 게임 프로필 또는 PC가 필요하다.

| 역할 | BepInEx | RepoHell | 기타 모드 |
| --- | --- | --- | --- |
| 방장 | 설치 | 설치 | 없음 |
| 참여자 A | 미설치 | 미설치 | 없음 |
| 참여자 B(선택) | 설치 가능 | 미설치 | 없음 |

참여자 A는 반드시 완전한 순정 프로필이어야 한다. 같은 게임 폴더를 공유하면서 실행 인자만 다르게 쓰는 경우 BepInEx가 실제로 비활성화됐는지 로그와 프로세스로 확인한다.

## 출시 전 필수 시나리오

### 연결과 수명 주기

- [ ] 순정 참여자가 모드 방장의 로비를 정상적으로 찾고 입장한다.
- [ ] 게임 시작과 첫 레벨 로딩이 완료된다.
- [ ] 레벨 전환과 트럭 복귀가 정상 동작한다.
- [ ] 상점 진입과 다음 레벨 시작이 정상 동작한다.
- [ ] 참여자가 중도 참가하거나 재접속해도 현재 상태를 받는다.
- [ ] 참여자가 나가도 남은 플레이어의 진행이 계속된다.
- [ ] 게임 종료 후 저장이 정상적으로 다시 열린다.

### 기능 경험

- [ ] 방장과 순정 참여자가 같은 핵심 사건과 결과를 관찰한다.
- [ ] 순정 참여자가 필요한 오브젝트를 보고 듣고 상호작용한다.
- [ ] 보상, 피해, 스폰, 진행 결과가 플레이어 간 일치한다.
- [ ] 기능 발동을 여러 번 반복해도 상태가 누적되거나 중복되지 않는다.
- [ ] 높은 지연과 패킷 손실 상황에서도 진행 불가 상태가 생기지 않는다.

### 안전성

- [ ] 순정 참여자 콘솔/로그에 반복적인 RPC 또는 역직렬화 오류가 없다.
- [ ] Missing prefab/component 관련 오류가 없다.
- [ ] 방장 로그에 처리되지 않은 예외가 없다.
- [ ] 호스트가 아닌 모드 설치자는 순정 방의 상태를 변경하지 않는다.
- [ ] RepoHell을 제거한 뒤 같은 저장으로 순정 게임을 진행할 수 있다.
- [ ] 기능이 비활성화된 설정에서는 순정 동작과 동일하다.

## 판정 기준

다음 조건을 모두 만족해야 C-001 통과로 판정한다.

- 필수 시나리오가 모두 통과한다.
- 순정 참여자가 기능의 핵심 경험에서 제외되지 않는다.
- 재현 가능한 오류, 연결 해제, 소프트락 또는 영구 상태 불일치가 없다.
- 순정 참여자에게 설치를 요구하는 우회책이 없다.

실패 항목이 하나라도 있으면 해당 기능은 출시할 수 없다. 수정 후 전체 혼합 로비 테스트를 다시 수행한다.
