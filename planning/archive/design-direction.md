# 게임 디자인 방향 (이전 기획)

## 해결하려는 문제

R.E.P.O.의 기본 루프는 탐색, 가치품 운반, 추출, 상점, 다음 스테이지로 이어진다. 맵·적·가치품과 순정 난이도 변화가 달라져도 익숙해진 플레이어는 결국 비슷한 판단과 동선을 반복하게 된다.

RepoHell의 목적은 이 루프를 교체하는 것이 아니다. **순정 루프 위에 매 스테이지 새로운 상황 규칙을 얹어, 같은 장소와 자원으로도 다른 판단·사고·협동이 발생하게 만드는 것**이다.

## 한 문장 기획

> RepoHell은 매 스테이지 순정 요소의 등장 방식과 관계를 바꾸는 하나의 명확한 변칙을 적용하여, 설치하지 않은 참여자도 플레이만으로 규칙을 발견하고 새로운 협동 상황을 즐기게 하는 호스트 전용 리플레이 확장 모드다.

## 디자인 기둥

### 1. 순정을 확장하고 대체하지 않는다

- 탐색, 물리 운반, 위험 관리, 추출이라는 원래 재미를 유지한다.
- 새 시스템을 별도로 공부시키지 않고, 익숙한 순정 요소의 관계만 바꾼다.
- 순정의 레벨·Moon Phase·난이도 변화와 경쟁하지 않고 그 위에 추가 변주를 만든다.

### 2. 설명보다 플레이로 이해시킨다

- 순정 참여자에게 커스텀 UI나 설명문을 보여줄 수 없다는 점을 디자인 장점으로 활용한다.
- 규칙은 첫 1~2분 안에 눈에 보이는 사건으로 드러나야 한다.
- 원인과 결과가 가까워야 한다. 예: 적을 쓰러뜨린 자리에 가치품이 나타난다면 별도 설명 없이도 반복을 통해 규칙을 배울 수 있다.
- 숨은 수치 변화보다 스폰, 위치, 타이밍, 조합처럼 관찰 가능한 변화를 우선한다.

### 3. 어려움보다 다른 선택을 만든다

단순히 적 체력, 피해량, 속도를 올리는 것은 반복 플레이를 더 피곤하게 할 뿐이다. 좋은 변칙은 다음 질문 중 하나를 바꾼다.

- 어디를 먼저 탐색할 것인가?
- 무엇을 가져가고 포기할 것인가?
- 언제 싸우거나 도망칠 것인가?
- 누구와 함께 움직일 것인가?
- 지금 더 욕심낼 것인가, 안전하게 끝낼 것인가?

### 4. 위험에는 읽을 수 있는 보상이 있다

- 강한 위험은 가치품 증가, 안전한 동선, 시간 절약 등 명확한 기회를 함께 제공한다.
- 플레이어가 위험을 강제로 견디는 대신 선택하도록 만든다.
- 손해만 주는 변칙은 짧게 사용하거나 다른 보상과 결합한다.

### 5. 한 판에는 한 가지를 기억하게 한다

- 기본값은 스테이지당 주요 변칙 1개다.
- 하나의 변칙은 한 문장으로 설명 가능해야 한다.
- 여러 변칙의 조합은 각 규칙이 검증된 뒤 후반 난이도에서만 허용한다.
- 같은 변칙을 연속으로 선택하지 않는다.

## 핵심 시스템: 스테이지 변칙

스테이지를 생성할 때 호스트가 호환 가능한 변칙 하나를 선택한다. 변칙은 순정 오브젝트와 기존 네트워크 동기화만 사용하여 스폰 구성, 배치, 사건 발생 시점 또는 보상 관계를 바꾼다.

### 변칙의 구성

| 요소 | 설명 |
| --- | --- |
| 판타지 | 플레이어가 기억할 상황을 한 문장으로 표현 |
| 변화 축 | 무엇 / 어디 / 언제 / 관계 중 무엇을 바꾸는지 |
| 텔레그래프 | 초반에 규칙을 알아차릴 수 있는 순정 신호 |
| 선택 | 평소와 다른 어떤 결정을 요구하는지 |
| 위험 | 실패하거나 욕심냈을 때 무엇을 잃는지 |
| 보상 | 위험을 감수할 이유 |
| 강도 | 진행도와 인원수에 따라 조절할 수치 |
| 호환 태그 | 맵, 적, Moon Phase, 다른 변칙과의 충돌 조건 |
| 복구 | 패치 실패 시 순정 동작으로 돌아가는 방식 |

## 플레이어 이해 설계

커스텀 UI 없이도 이해시키기 위해 모든 변칙은 다음 순서를 따른다.

1. **예고:** 익숙한 요소가 평소와 다르게 배치되거나 등장한다.
2. **안전한 시범:** 치명적인 손해가 없는 작은 사례로 원인과 결과를 보여준다.
3. **반복:** 같은 관계가 두세 번 반복되어 우연이 아님을 알린다.
4. **확대:** 스테이지 중후반에는 더 큰 위험과 보상으로 발전한다.
5. **회수:** 추출이나 보상으로 그 스테이지의 이야기가 마무리된다.

규칙을 이해하지 못하면 즉시 죽거나 진행이 막히는 설계는 피한다. 첫 조우는 학습 기회여야 한다.

## 진행과 강도

### 초기 스테이지

- 변칙 하나만 적용한다.
- 기존 규칙을 뒤집기보다 스폰과 보상을 눈에 띄게 재배치한다.
- 첫 사건은 빠르고 비교적 안전하게 보여준다.

### 중간 스테이지

- 같은 변칙의 수량, 빈도 또는 위험 반경을 높인다.
- 팀을 모으거나 흩어지게 만드는 선택을 추가한다.
- 순정 난이도가 높은 판에서는 변칙 강도를 낮춰 과도한 중첩을 막는다.

### 후반 스테이지

- 충분히 학습된 변칙 두 개를 제한적으로 조합할 수 있다.
- 보상도 함께 커져야 한다.
- 조합은 사전에 정의된 호환표를 사용하며 완전 무작위로 섞지 않는다.

## 변칙 선택 알고리즘 원칙

- 최근 3개 스테이지에서 나온 변칙은 가중치를 크게 낮춘다.
- 현재 레벨, 순정 난이도, 플레이어 수와 충돌하는 변칙은 후보에서 제외한다.
- 전체 위험 예산을 계산한 뒤 순정 변화가 강한 스테이지에서는 RepoHell 강도를 낮춘다.
- 같은 변화 축만 반복하지 않는다. 예: 적 구성 변칙 다음에는 배치나 보상 변칙을 우선한다.
- 선택 결과와 제외 이유를 방장 로그에 남겨 밸런싱 자료로 사용한다.

## 하지 않을 것

- 모든 적의 체력과 피해량을 일괄 증가시키기
- 플레이어가 알 수 없는 숨은 확률로 갑자기 처벌하기
- 여러 규칙을 첫 스테이지부터 동시에 적용하기
- 순정 참여자가 볼 수 없는 전용 UI에 핵심 정보를 표시하기
- 특정 정답 행동만 강요하여 자유로운 물리 플레이를 막기
- 순정 난이도 변화와 무관하게 계속 강도만 올리기

## 성공 기준

플레이테스트 후 플레이어가 다음 질문에 답할 수 있어야 한다.

- “이번 스테이지는 무엇이 달랐나?”
- “그래서 우리 팀은 평소와 무엇을 다르게 했나?”
- “위험을 감수할 이유가 있었나?”
- “다음에 같은 변칙이 나오면 다른 전략을 시도하고 싶은가?”

변칙 이름을 정확히 맞히는 것은 중요하지 않다. 플레이어가 변화의 관계를 이해하고 새로운 이야기를 만들었다면 성공이다.
